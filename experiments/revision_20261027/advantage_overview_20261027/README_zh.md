# DAS 与 NEAR：协议提交单元计数审计

## 主场景与结果

场景为通用状态化工作流：8 个独立合约构成串行依赖链，7 条依赖边，每会话一个工作流。每个节点执行相同确定性运算、保存自身状态，并使用前驱的实际输出。两端逐节点输入与校验和一致。

图表以表格列出深度 2、4、8 时每个工作流对应的协议级提交单元绝对数量：NEAR 为每个独立节点收据分别提交，DAS 本地组合由一笔 Router 外层交易提交。这是执行/持久化边界的机制核验，不能解读成 8:1 的工作量或性能优势，也不应按节点数外推性能倍数。

- 计数表：[PNG](das_vs_near_direct.png) / [矢量 SVG](das_vs_near_direct.svg)。
- 趋势：深度 2 / 4 / 8，NEAR 为 2 / 4 / 8 批；DAS 本地组合均为 1 批。
- 每配置三个新建运行时，每运行时两个会话，共六个成功观测；该计数在六次观测中完全一致。

## 指标定义与核验

统一指标是“工作流内部协议级状态提交单元数”。它是执行/持久化边界的计数，不是用户交易数，也不是吞吐量、延迟、加速比或各平台的 gas。

- NEAR：只统计产生日志 `DAG_NODE` 的独立成功执行收据。callback、system refund、发起交易的 nonce/费用更新、部署与初始化均不计入此指标。
- DAS 本地执行：统计将所有独立 Stage 调用统一提交的成功 Router 外部交易。每个 Stage 有独立地址和 storage，原始记录中的 external CALL、节点事件和输入核验确认了实际多合约调用，而非把节点合并成单合约循环。
- 脚本逐会话核对节点数、独立地址、执行成功、输入与校验和。原始证据 ID、输入文件 SHA-256 和聚合数据见 [metric_audit.json](metric_audit.json)；绘图值见 [CSV](direct_comparison.csv)。

两侧的提交单元语义不同：EVM 的一笔外层交易把所有 Stage 写入作为一个原子整体，失败时整体回滚；NEAR 的节点收据分别执行和持久化，失败时先前成功的收据可以保留。因此该计数不能解释为等价交易数，也不能据此声称性能收益或“节点数倍加速”。图不包含迁移、认证或最终性证明成本。entry/exit 代理与部署成本也不等于真实桥接成本。

## 适用范围

主场景保留应用的独立合约边界。NEAR 同 receiver 合并控制也能一次提交；Avalanche/Teleport 迁入后同域本地执行也具有本地组合能力。该计数表只用于审计所测执行路径如何划分提交边界，不作为论文性能结果或对这些方案的性能比较。

NEAR 数据来自实际 nearcore 2.14.0 / protocol 88 Sandbox，DAS 本地执行数据来自远程 Anvil 1.8.6 的独立 Stage + Router 全矩阵。此次只读取已有结果、核查和绘图，没有在本机启动任何实验。

远程 1 秒区块周期的小样本计时试跑已完成：NEAR d2/d4/d8 首次观察到 sink 状态可查询约为 4.04/6.03/10.06 秒，EVM 对应约为 1.00/0.96/1.00 秒。每个深度当前只有一个样本；测量脚本/查询路径和完整重复实验仍需审计，因此这些数字仅用于发现方法学问题，不作为论文结论。无论后续时间结果如何，都不能把本图的提交单元计数换算成时间比或性能倍数。
